# Research: 学情分析模块深度 AI 赋能 — AI 学习教练

## Research Question

把学情模块从"无时间维度的横截面读物"升级为具备**深度错因诊断（FR1）+ 可执行计划-任务（FR2）+ 掌握闭环（FR3）+ 长期趋势跟踪（FR4）**完整链路的 AI 学习教练，全部建在既有 Fastify + SQLite + pi SDK + React 之上。研究重点是解答 FRD 的 8 个 Open Questions（落库口径、掌握判定、任务映射、快照触发、AI 结构化产出）。

## Summary

系统的数据地基完全支撑这次升级，且**不需要重型改造**：

- **深度错因数据已具备**：`attempts.user_answer`（JSON 完整作答）+ `questions.stem/options/answer` + tutor JSONL 会话，三者齐全，能让 AI 看到"你具体选了哪个错误选项"。但当前 `LearningDataCollector.queryAttemptTags()` **故意只 SELECT `is_correct, tags`**（`LearningDataCollector.ts:36-49`）——错因诊断需要一个**保留每题细节的新 collector**。
- **掌握闭环是纯空白**：mastery 100% 手动（`wrongBookRepo.setMastered` 仅被一个按钮路由调用），判分后（`quiz.ts:92`）**零 post-hook**、零 streak 追踪。FR3 需要新建 `mastery_states` 表 + 判分 hook。
- **快照无时间维度**：`LearningSnapshot`（`types.ts:104-113`）只有 4 个字段、无 `timestamp`、无 per-tag 时间序列。FR4 需要新建 `insight_snapshots` 表，在**练习完成时**（新增 `/practice/:id/finish`）落一个数据点——单实例本地部署无 cron。
- **任务一键开练的桥已现成**：`POST /api/practice/start` 直接接受任意 `PracticeScope`（`quiz.ts:113-128`，无白名单），任务只需存一个 `PracticeScope` JSON 再 POST 即可。唯一 gap：前端 `DrillFilter` 只带 `{bankId,tag,type}`，需扩到完整 `PracticeScope`（含 `mode`+`shuffle`）。
- **AI 结构化产出有现成模板**：导入解析的 `runOnce + extractJsonArray + zod 校验`（`parseWithAi.ts`）是错因归类/计划/任务落库的精确范式——用 `runOnce`（非 `streamPrompt`）拿完整 JSON 再解析。
- **新表落地是成熟套路**：v2 commit `461ecec` 是 27 文件的新表全流程范例（shared 类型 → schema → repo → route → client），层优先、只加新表不改列。

## Detailed Findings

### FR1 — 深度错因诊断（数据前提与调用路径）

- 当前 `LearningDataCollector.collect()`（`LearningDataCollector.ts:23-32`）产出 `{ totalAttempts, accuracy, weakTags, tutorHighlights }`——聚合统计，**无每题细节**。
- `queryAttemptTags()`（`LearningDataCollector.ts:36-49`）的 SQL 只 `SELECT a.is_correct, q.tags`，`AttemptTagRow`（`LearningDataCollector.ts:27`）确认这是刻意最小化。**不含** `q.stem/options/answer`、`a.user_answer`、`a.id`。
- 错因诊断需要新方法 join `attempts × questions` 拿 `{stem, options, correctAnswer, userAnswer, isCorrect}` for wrong questions。`attemptRepo.listWrongDetailed()`（`attemptRepo.ts:58-81`）返回聚合的 `wrongCount/lastWrongAt`，**不含 user_answer**——需新 query。
- tutor 会话：`readSessionHistory(jsonlPath)`（`sessionHistory.ts:28`）→ `HistoryTurn[]`；`tutor_sessions` 表按 `question_id` 关联（`schema.ts:33`），可拿到某题的完整答疑对话喂给诊断 prompt。
- **决策**：错因用固定枚举（概念混淆/计算失误/审题不仔/知识盲区）让 AI 分类，结果**落库**（供趋势统计错因模式变化）。

### FR2 — 可执行计划-任务（PracticeScope 桥接）

- `PracticeScope`（`types.ts:123-128`）：`{ bankId, mode: 'all'|'undone'|'wrong'|'byType'|'byTag', type?, tag?, shuffle? }`。
- `resolveScopeQuestions(scope)`（`quiz.ts:21-51`）把每种 mode 解析为题集；`shuffle` 走 Fisher-Yates（`quiz.ts:50`）。
- `POST /api/practice/start`（`quiz.ts:113-128`）**直接接受任意 PracticeScope**，仅校验 `bankId/mode` 存在 + bank 存在，无 mode 白名单。→ 任务存 `PracticeScope` JSON 即可一键开练。
- `practiceRepo.create()`（`practiceRepo.ts:33-49`）把 `questionIds` 与 `scope` 序列化为 JSON 存 `practice_sessions`，冻结解析后的顺序。
- **前端下钻 gap**：`InsightsPanel` 的 weak-tag 点击走 `onDrillTag`，当前 `DrillFilter` 只带 `{bankId,tag,type}`，需扩展到完整 `PracticeScope`（补 `mode`+`shuffle`）才能承载任务跳转；`QuizPage` 需支持进入时消费预置 scope。

### FR3 — 掌握闭环（连续 N 次达标自动判定）

- **现状 100% 手动**：`wrongBookRepo.setMastered()`（`wrongBookRepo.ts:18-28`）是唯一 mastery 写入点，仅被 `POST /api/quiz/wrong/:questionId/master`（`quiz.ts:119-130`）调用。
- `wrong_book_state`（`schema.ts:64-67`）只有 `is_mastered/mastered_at`，**无 streak 列**。判分（`quiz.ts:92`）后立即返回，**无 post-hook**。全库零 `streak/consecutive/连续` 匹配。
- `attempts` 是 append-only（每答一题 INSERT，无 upsert），"最新作答"靠 `ORDER BY answered_at DESC`。
- **决策**：新建 `mastery_states` 表（`question_id, consecutive_correct, mastered`），判分后加 hook 更新连续计数，达阈值自动写 `wrong_book_state.is_mastered`（两者兼容）。需新增 `attemptRepo.recentAttemptsByQuestion()` + 复合索引 `idx_attempts_question_time ON attempts(question_id, answered_at DESC)`。

### FR4 — 长期趋势跟踪（快照落库 + 时间序列）

- `LearningSnapshot`（`types.ts:104-113`）无 `timestamp`、无 per-tag 时间序列——需新表 + 新类型。
- `buildScorecard()`（`quiz.ts:169-206`）已产出 `byTag: {tag,total,correct}[]` + `accuracy`，**正好映射** `insight_snapshots.by_tag`。`byTag`（correct 视角）与 `WeakTag`（wrong 视角）是同数据两面。
- **决策**：新建 `insight_snapshots` 表（`session_id, bank_id, total, correct, accuracy, by_tag(JSON), by_type(JSON), created_at`），**在练习完成时**（新增 `POST /api/practice/:id/finish`）落一个数据点。单实例无 cron，练习完成是最自然的语义化触发点。
- per-tag 趋势查询用 `json_each(s.by_tag)` + `json_extract` 按 tag 抽时间序列（SQLite JSON1）。

### FR5 / AI 调用模式

- `runOnce(systemPrompt, userPrompt)`（`AiService.ts:99-125`）：inMemory 一次性会话，返回完整 text，用完 dispose。导入解析用它。
- `streamPrompt()`（`AiService.ts` 尾部）：SSE 逐块回调，insights/analyze 与 tutor 用它。
- 导入解析的结构化提取范式（`parseWithAi.ts`）：system prompt 要求"只输出 JSON 数组、无 markdown 围栏" → `extractJsonArray` 兜底找 `[...]` → zod `questionDraftSchema`（`questionSchema.ts:13-47`，`superRefine` 跨字段校验）验证。
- **决策**：错因归类/计划/任务用 `runOnce` 拿结构化 JSON（**非 streamPrompt**，因为需完整文本才能解析）落库；人读的深度报告仍走 SSE 流式（延续 DEC-24）。

## Architecture Insights

- **层优先（proven）**：v2 plan 明确"Slice 1 是地基，Slice 2-7 全依赖它"——shared 类型 → schema → repo 必须先于 route/client。跨层并行历史上都产生了 follow-up fix。
- **无 migration → 只加新表不改列**：schema 无版本表、无 migration runner，`CREATE TABLE IF NOT EXISTS` 幂等。加列需 `getDb()` 里加 try/catch 守卫的 `ALTER TABLE`（无 IF NOT EXISTS）。v2 设计刻意"优先新表、避免加列"，本次沿用——4 张新表（insight_snapshots / learning_plans / learning_tasks / mastery_states），零改列。
- **结构化 AI 产出用 runOnce 不用 streamPrompt**：streamPrompt 给 chunk，结构化数据需完整文本才能解析；runOnce 已缓冲完整文本，配 extractJsonArray + zod 是正确选择。若需进度提示，可 streamPrompt 仅做"思考中"指示，但解析用完整文本。
- **JSON 列范式**：scope/question_ids 以 JSON string 存列，repo 层 `toEntity()` 解析（见 practiceRepo）。快照的 by_tag/by_type 同法，查询用 SQLite JSON1 的 `json_each`/`json_extract`。
- **attempts append-only**：无 upsert，最新作答靠 `ORDER BY answered_at DESC LIMIT 1`；掌握 streak 靠"最近 K 条倒序遍历，遇错中断计数"。

### Composite Lessons
