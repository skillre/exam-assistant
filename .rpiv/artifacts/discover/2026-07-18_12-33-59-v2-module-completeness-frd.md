# FRD — v2 五大板块功能完整度补齐

## Problem & Intent（问题与意图）

MVP（v1）已跑通客观题刷题闭环：导入 → 判分 → AI 讲解/答疑 → 错题 → 学情。
但每个板块都停留在"能用"，缺少让学生**高频、长期使用**所必需的功能完整度：

- 刷题没有阶段性反馈（做完一套没有成绩单），无法只做未做/只做某类题；
- 错题本只是一个列表，无法标记"已掌握"、无法按知识点筛选；
- 学情后端已算出 `weakTags` 结构化数据，前端却只渲染一段 AI 文本，数据白算；
- 导入预览不能编辑就只能"照单全收"，设置页无法验证 Key 是否可用。

本轮意图：**在不改变 MVP 架构与既有决策（DEC-1..21）的前提下，把五个板块补齐到"日常可长期使用"的完整度**。

核心用户不变：备考学生（自学、刷题为主）。

## Goals（目标）

1. 刷题闭环从"逐题判分"升级为"**有范围、有筛选、有进度、有成绩单**"的完整练习会话。
2. 错题本从"只读列表"升级为"**可管理的复习工具**"（标记掌握、筛选、重做闭环）。
3. 学情从"一段文本"升级为"**结构化可视化 + AI 文本**"双呈现。
4. 导入从"照单全收"升级为"**预览可编辑纠错**"；设置页支持"**连通性验证**"。

## Non-Goals（本期不做）

- ❌ 不改 MVP 已定架构决策（DEC-1..21 全部继承）。
- ❌ 不做主观题（继承 DEC-1）。
- ❌ 不做内置题库/AI 实时出题（继承 DEC-2）。
- ❌ 不做多端同步、账号体系、协作。
- ❌ 不引入新的重型依赖（图表优先用轻量方案或纯 CSS/SVG，不引入大型 BI 库）。
- ❌ 不做移动端原生 App（响应式 Web 即可）。

## Functional Requirements（功能需求）

### FR1 — 答题闭环增强（Quiz）

- **FR1.1 练习范围与筛选**：开始刷题前可选范围 —— 全部 / 仅未做 / 仅错过 / 按题型 / 按知识点标签。
- **FR1.2 顺序控制**：支持顺序 / 乱序（shuffle）。
- **FR1.3 进度持久化与续做**：一套练习的作答进度可保存，刷新/重进后可继续（resume）。
- **FR1.4 题目跳转**：题号导航，可跳到任意题；已答/未答/对错状态在导航上可见。
- **FR1.5 成绩单**：一套练习结束给出成绩单（正确率、用时、按题型/知识点的对错分布、错题快速入口）。
- **FR1.6 键盘操作**：数字键选选项、Enter 提交、方向键翻题（渐进增强，非必须但纳入范围）。

### FR2 — 错题本增强（WrongBook）

- **FR2.1 掌握标记**：可将错题标记为"已掌握"，从错题本移除（软移除，可恢复）。
- **FR2.2 筛选与分组**：按题库 / 题型 / 知识点标签筛选；可按知识点分组展示。
- **FR2.3 错题计数与统计**：每题显示错误次数、最近错误时间。
- **FR2.4 重做闭环**：错题重做答对后，提示可标记掌握。

### FR3 — 学情可视化（Insights）

- **FR3.1 结构化面板**：把后端已产出的 `LearningSnapshot`（totalAttempts / accuracy / weakTags / tutorHighlights）以可视化面板呈现（正确率、薄弱知识点条形/占比、答疑要点）。
- **FR3.2 AI 文本报告保留**：结构化面板与现有 SSE 文本报告并存（面板先出，AI 文本按需生成）。
- **FR3.3 快照即时性**：结构化面板从 REST 即时拉取（非 SSE），进入页面即可见，无需等 AI。
- **FR3.4 薄弱点下钻**：点击某薄弱知识点，可跳转到"按该标签筛选"的刷题/错题视图（与 FR1.1/FR2.2 联动）。

### FR4 — 导入增强（Import）

- **FR4.1 预览可编辑**：AI 解析/文件解析后的草稿，在入库前可逐题编辑（题干、选项、答案、题型、标签、解析）。
- **FR4.2 草稿增删**：预览列表可删除某题、可手动新增一题。
- **FR4.3 校验提示**：入库前校验（答案越界、选项为空、多选无答案等）并提示。

### FR5 — 设置增强（Settings）

- **FR5.1 连通性验证**：provider 配置后可点"测试连接"，后端用已存 Key 发一次最小请求验证可用性（成功/失败 + 原因），Key 不回传前端。
- **FR5.2 模型可用性反馈**：测试结果与当前激活模型状态在设置页清晰可见。

## Non-Functional Requirements（非功能需求）

- **NFR1**：继承 MVP 全部安全约束 —— Key 只在后端、加密存储、永不回传（含 FR5.1 测试也不回传 Key）。
- **NFR2**：结构化数据（成绩单、学情面板、错题统计）走 REST，首屏即时；AI 文本仍走 SSE 流式。
- **NFR3**：类型贯通 —— 新增的 API 契约与数据结构一律加入 `@exam/shared`，前后端共享。
- **NFR4**：进度持久化落 SQLite（与既有 attempts/questions 一致），不引入新存储。
- **NFR5**：可视化不引入重型依赖，优先纯 CSS/SVG 或极轻量方案。
- **NFR6**：所有构建/运行/测试遵循 DEC-15/16（Docker + SSH + Git 中转，本地不跑）。

## Acceptance Criteria（验收标准）

- [ ] 刷题可选"仅未做/仅错过/按题型/按标签"范围并支持乱序。
- [ ] 刷题进度可续做；有题号导航与对错状态。
- [ ] 一套练习结束展示成绩单（正确率/用时/分布/错题入口）。
- [ ] 错题可标记"已掌握"并从错题本移除，可按标签/题型/题库筛选。
- [ ] 错题显示错误次数与最近错误时间。
- [ ] 学情页进入即见结构化面板（正确率 + 薄弱知识点可视化 + 答疑要点），AI 文本报告仍可生成。
- [ ] 学情薄弱点可下钻到对应筛选视图。
- [ ] 导入预览可逐题编辑/增删，入库前有校验提示。
- [ ] 设置页可"测试连接"，返回成功/失败且不回传 Key。
- [ ] 所有新增 API 契约在 `@exam/shared` 定义，前后端共享。

## Decisions（供下游 research / design 继承）

沿用 MVP 的 **DEC-1..DEC-21**（见 source_mvp_design），本轮新增：

1. **DEC-22**：v2 = **功能完整度补齐**，不做架构重构；一切建立在既有 Fastify + SQLite + pi SDK + React 之上。
2. **DEC-23**：范围 = 五个板块全部增强（答题闭环 / 错题本 / 学情可视化 / 导入 / 设置）。
3. **DEC-24**：结构化数据（成绩单、学情面板、错题统计、连接测试结果）一律走 **REST 即时返回**；AI 生成内容继续走 **SSE 流式**（延续 DEC-8）。
4. **DEC-25**：练习进度持久化落 **SQLite**（新增会话/进度表或复用 attempts + 派生），不引入新存储（延续 DEC-4/NFR4）。
5. **DEC-26**：可视化**不引入重型图表库**，优先纯 CSS/SVG 或极轻量实现（NFR5）。
6. **DEC-27**：连接测试用后端已存**解密 Key 发一次最小模型请求**验证，结果回传但 **Key 绝不回传**（延续 DEC-19/NFR1）。
7. **DEC-28**：错题"已掌握"用**软标记**（可恢复），不物理删除 attempts（保留学情数据完整性）。

## Open Questions（待 research/design 阶段解答）

- OQ1：练习"进度/会话"是新建 `practice_sessions` 表，还是从 attempts 派生"未做/已做"？续做的粒度（一套题的 idx + 已答映射）如何落库最简。
- OQ2："仅未做/仅错过"的判定口径 —— 基于 attempts 是否存在 / 是否有 is_correct=0 记录？多次作答如何取最新？
- OQ3：错题"已掌握"软标记落在哪 —— attempts 加列、questions 加列、还是新建 `wrong_book_state` 表？如何与"重做答对"联动。
- OQ4：学情结构化面板复用现有 `/api/insights/analyze`（SSE）还是新增 `GET /api/insights/snapshot`（REST）？（倾向后者，延续 DEC-24）
- OQ5：连接测试的"最小请求" —— 用 pi SDK 发一条极短 prompt，还是调用 provider 的 models 列表端点？超时与错误如何归类。
- OQ6：导入预览编辑后的草稿校验规则集中放在 shared（前后端复用）还是仅后端 commit 时校验？
