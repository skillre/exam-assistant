# Feature Requirements Document — AI 原生考试助手

## Problem & Intent（问题与意图）

> 备考学生在做题/刷题时，最痛的不是"判对错"（程序就能做），而是**做完题后没人讲、错了不知道为什么错、错完就忘、不知道自己哪块知识薄弱**。

核心用户：**备考学生**（自学、刷题为主）。
核心场景：学生打开工具 → 导入自己的题目 → 刷客观题（选择/判断）→ 程序即时判分 → **AI 逐题讲解 + 针对错题多轮答疑 + 归纳错因与学情**。

"AI 原生"的落点：客观题判分是确定性的，AI 的价值集中在**讲解、追问答疑、错因归纳、以及导入时的题目解析**——这些是传统题库工具做不到的部分。

## Goals（目标）

1. 让学生能**零门槛导入自己的题目**（粘贴文本由 AI 解析，或结构化文件导入）。
2. 跑通**客观题刷题闭环**：做题 → 即时判分 → AI 讲解 → 错题答疑 → 错因/学情归纳。
3. AI 交互是**多轮、流式、有上下文**的（基于 pi agent SDK）。
4. 做题记录、错题本、题库持久化，支持复习。

## Non-Goals（本期不做）

- ❌ 主观题/问答题的 AI 批改（明确推迟到 v2；MVP 只做客观题）。
- ❌ AI 实时出题 / 内置题库（内容全部由用户导入）。
- ❌ 多端同步、社交、班级/组织管理。
- ❌ 移动端原生 App（先做浏览器 Web 应用，响应式即可）。
- ❌ 本地开源模型部署（先用可切换的云端/国内模型 API）。

## Functional Requirements（功能需求）

### FR1 — 题目导入
- **FR1.1 粘贴文本 + AI 解析**：用户粘贴任意格式的题目文本，AI 解析为结构化题目（题干、选项、正确答案、题型、可选解析/知识点标签）。
- **FR1.2 结构化文件导入**：支持 JSON / CSV / Excel 导入，按约定 schema 直接入库（不走 AI，快速可靠）。
- **FR1.3 导入预览与纠错**：AI 解析结果先展示给用户确认/编辑，再入库。

### FR2 — 刷题闭环
- **FR2.1 题型**：单选、多选、判断（客观题，确定性判分）。
- **FR2.2 即时判分**：程序判分，不经过 AI。
- **FR2.3 逐题讲解**：判分后 AI 讲解"为什么对/为什么错"，流式输出。
- **FR2.4 错题追问答疑**：针对当前题进入多轮对话，AI 保留题目与作答上下文。

### FR3 — 错题与学情
- **FR3.1 错题本**：自动收集错题，支持重做。
- **FR3.2 错因归纳 + 学情分析**：AI 基于做题记录归纳薄弱知识点/常见错因。

### FR4 — 数据持久化
- 题库、题目、做题记录、错题、AI 会话历史落库（SQLite）。

## Non-Functional Requirements（非功能需求）

- **NFR1 安全**：AI 模型 API Key 只存后端，绝不下发前端；后端代理所有模型调用。
- **NFR2 流式体验**：AI 讲解/答疑走流式（SSE 或 WebSocket），首字节尽量快。
- **NFR3 模型可切换**：模型接入通过 pi SDK / OpenAI 兼容层，便于切换云端/国内模型。
- **NFR4 数据本地掌控**：SQLite 单文件，用户数据留在自己的部署里。
- **NFR5 可维护**：前后端同为 TypeScript，类型贯通（题目/作答/会话的共享类型）。

## Constraints & Tech Stack（约束与技术栈）

| 维度 | 决策 | 理由 |
|------|------|------|
| 形态 | Web 应用（浏览器） | 用户已定 |
| 前端 | React + Vite + TypeScript | 用户已定 |
| 后端 | Node.js + TypeScript | pi agent SDK 是 Node/TS 包，天然约束 |
| AI 能力 | **pi agent SDK**（`@earendil-works/pi-coding-agent`），`createAgentSession()` + 事件流 | 用户指定用智能体框架 |
| 模型接入 | 经 pi SDK 的 ModelRegistry / OpenAI 兼容接口，可切换 | 兼顾能力与国内可用性 |
| 数据库 | SQLite | 用户已定，MVP 轻量 |
| 架构 | 前后端分离 + 数据库 | 用户已定 |

## Acceptance Criteria（验收标准）

- [ ] 用户可粘贴一段题目文本，AI 解析出结构化题目并可确认入库。
- [ ] 用户可导入一个 JSON/CSV/Excel 文件，题目正确入库。
- [ ] 用户可对一套题逐题作答，程序即时判分。
- [ ] 每题判分后可看到 AI 流式讲解。
- [ ] 用户可就某道错题与 AI 多轮追问，AI 记得题目上下文。
- [ ] 错题自动进入错题本，可重做。
- [ ] 用户可查看 AI 生成的错因归纳/学情分析。
- [ ] 模型 API Key 不出现在任何前端网络响应中。

## Decisions（供下游 research / design 继承）

1. **DEC-1**：MVP 只做**客观题闭环**，主观题 AI 批改推迟到 v2。
2. **DEC-2**：题目来源 = **用户导入**（粘贴 AI 解析 + 结构化文件）；不做内置题库/实时出题。
3. **DEC-3**：AI 职责 = 讲解 / 错题多轮答疑 / 错因归纳学情 / 导入解析；**判分不用 AI**。
4. **DEC-4**：技术栈 = React+Vite+TS（前端）/ Node+TS（后端）/ SQLite（库）。
5. **DEC-5**：AI 通过 **pi agent SDK** 接入，后端持有 Key 并代理，前端不碰模型。
6. **DEC-6**：AI 输出走**流式**；模型**可切换**（OpenAI 兼容 / ModelRegistry）。

## Open Questions（待 research/design 阶段解答）

- OQ1：pi SDK 的 `createAgentSession` 会话如何映射到"每道题一个答疑会话"？会话历史是持久化在 SDK 的 SessionManager 还是我们自己的 SQLite？
- OQ2：题目结构化 schema 的最小字段集？（题干/选项/答案/题型/知识点标签/解析）
- OQ3：多轮答疑上下文如何注入（题目+作答+判分结果）到 agent？
- OQ4：流式传输选 SSE 还是 WebSocket？
- OQ5：模型如何配置（.env / 设置页），如何做"可切换"？
