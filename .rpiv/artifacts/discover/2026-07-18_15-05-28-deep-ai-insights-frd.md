# FRD — 学情分析模块深度 AI 赋能（AI 学习教练）

## Problem & Intent（问题与意图）

> 以下为开发者本人的原话框定，未经改写：

用户要"针对学情分析模块进行深度 AI 赋能"，让 AI 深度分析自己的学习情况、错题情况，并针对个人情况有专门的提升成绩的设计能力。追问核心痛点时，用户明确"上面的 1、2、3、4 都是"——即**四类痛点全部命中**：

1. **不知道自己弱在哪**：刷了很多题，但看不清到底哪个知识点、哪种题型是短板，缺乏一个能"诊断病灶"的分析。
2. **知道弱点但不知怎么补**：大概知道哪里差，但没有具体、可执行的提升路径——不知道下一步该练什么、怎么练、练多少。
3. **错题看了就忘 / 没闭环**：错题记录下来了，但缺乏针对性的复盘、重练、变式训练机制，同样的错反复犯。
4. **缺少长期规划和反馈**：想要 AI 像私人教练一样，持续跟踪进步、动态调整策略，而不只是一次性出个报告。

**现状边界（代码探测确认）**：
- 后端 `LearningDataCollector`（`packages/server/src/insights/LearningDataCollector.ts:21`）产出的是**无时间维度的横截面快照** —— 只有 `totalAttempts / accuracy / weakTags / tutorHighlights`，能算"此刻整体正确率、哪些知识点错得多"，但算不出"这周比上周进步没、某薄弱点在好转还是恶化"。
- AI 只做**一次性文本报告**（`insightsPrompts.ts:5` — 概述 + 2-4 个薄弱点 + 3 条建议），是纯读物，看完即止，不落地成可执行任务。
- 错题本只有"已掌握"软标记（`wrongBookRepo.ts:16`），无重练调度、无掌握判定逻辑。

**本轮意图**：把学情模块从"横截面读物"升级为**具备诊断-方案-闭环-趋势完整链路的 AI 学习教练**——不改架构，建在既有 Fastify + SQLite + pi SDK + React 之上。

核心用户不变：备考学生（自学、刷题为主、单实例本地部署）。

## Goals（目标）

1. **深度诊断病灶**：AI 结合题目内容、用户选的错误选项、答疑追问，归纳"你为什么错"（概念混淆 / 计算失误 / 审题不仔 / 知识盲区），而非只统计"哪个知识点错得多"。
2. **可执行提升方案**：AI 产出分阶段学习计划 + 拆解成"一键开练"的具体任务（如"重练 X 知识点 10 题""复盘这 5 道高频错题"），点一下直接进入对应练习视图。
3. **错题闭环重练**：任务完成后系统按"连续多次稳定达标"判定掌握，掌握后自动更新薄弱点状态并反映到下一次分析，防侥幸。
4. **长期趋势跟踪**：引入时间维度，跟踪**整体正确率曲线** + **每个知识点各自的好转/恶化趋势**，AI 基于趋势动态调整策略——真正的"私人教练持续跟踪"。

## Non-Goals（本期不做）

- ❌ 不改既有架构决策（继承 MVP DEC-1..21 + v2 DEC-22..28）。
- ❌ 不引入新存储/分析引擎（时序库、向量库等）——全部建在 SQLite 之上。
- ❌ 不做主观题（继承 DEC-1）。
- ❌ 不做多端同步、账号体系、协作。
- ❌ 不引入重型图表库（趋势可视化优先纯 CSS/SVG 或极轻量方案，延续 DEC-26）。
- ❌ AI 不做"进页面自动全分析"——面板即时（REST），AI 深度产出按需触发（避免每次进页面都耗模型调用）。

## Functional Requirements（功能需求）

### FR1 — 深度错因诊断（Diagnosis）

- **FR1.1 错因归类**：AI 结合题目内容、用户选的错误选项（`attempts.user_answer` 已存 JSON 完整作答）、答疑追问记录，为错题归纳错因类型（如概念混淆 / 计算失误 / 审题不仔 / 知识盲区），而非仅统计知识点分布。
- **FR1.2 干扰项分析**：统计错误选项分布——哪个错误选项被选最多，作为错因归类的结构化信号。
- **FR1.3 病灶报告**：AI 深度报告输出"你最薄弱的知识点是什么、为什么错、错因模式是什么"，可操作、不空泛。

### FR2 — 可执行提升方案（Plan & Tasks）

- **FR2.1 分阶段学习计划**：AI 产出多天/多阶段学习计划（如"未来 3 天：周一攻 X，周二攻 Y"），落库为结构化记录，可缓存、可追溯。
- **FR2.2 任务拆解**：计划拆解成结构化、可执行的具体任务（重练某知识点 N 题 / 复盘某组高频错题），每个任务落库并带完成状态。
- **FR2.3 一键开练**：点击任务直接跳转到对应筛选的练习/错题视图（复用既有 PracticeScope byTag/wrong 等 mode，与 v2 FR1.1/FR2.2 联动）。
- **FR2.4 计划动态重排**：AI 根据最新进度重新生成/调整计划（按需触发，非自动）。

### FR3 — 错题闭环与掌握判定（Mastery Loop）

- **FR3.1 掌握判定规则**：任务/知识点需**连续多次稳定达标**才算掌握（如连续 N 次正确率 ≥ 阈值），防侥幸——不是单次达标即掌握。
- **FR3.2 自动闭环**：达标后系统自动标记任务完成、更新该薄弱点掌握状态，下一次分析自动感知（不需手动确认）。
- **FR3.3 状态回流**：掌握状态与错题本"已掌握"软标记（DEC-28）协同——掌握判定可驱动/联动软标记状态。

### FR4 — 长期趋势跟踪（Trend Tracking）

- **FR4.1 阶段快照落库**：新增快照表，周期性/触发式固定落库当期的整体正确率 + 每知识点正确率/错题数，形成时间序列数据点（不每次从 attempts 现算）。
- **FR4.2 整体趋势曲线**：整体正确率、错题量随时间的曲线。
- **FR4.3 知识点趋势**：每个知识点标签各自的好转/恶化趋势（AI 可表述"X 在进步、Y 在退步"）。
- **FR4.4 趋势解读**：AI 基于时间序列解读趋势，并据此调整 FR2 的计划（趋势 → 策略）。

### FR5 — 呈现与调用时机（Presentation）

- **FR5.1 面板即时**：进学情页即时看到结构化面板（正确率、薄弱点、趋势图）——走 REST，不耗模型调用（延续 DEC-24）。
- **FR5.2 AI 按需生成**：深度错因报告 / 计划 / 任务拆解由用户点"生成"按钮触发，AI 文本走 SSE 流式（延续 DEC-8/24），结构化产出落库缓存。
- **FR5.3 缓存与追溯**：AI 生成的报告/计划/任务缓存落库，可追溯历史；数据有明显变化或手动刷新时才重算。

## Non-Functional Requirements（非功能需求）

- **NFR1**：继承 MVP + v2 全部安全约束——Key 只在后端、加密存储、永不回传。
- **NFR2**：结构化数据（面板、趋势、快照）走 REST 即时；AI 生成内容走 SSE 流式（延续 DEC-24）。
- **NFR3**：类型贯通——新增 API 契约与数据结构一律加入 `@exam/shared`，前后端共享（延续 NFR3）。
- **NFR4**：新增数据（阶段快照、学习计划、任务）落 SQLite，不引入新存储（延续 NFR4/DEC-25）。
- **NFR5**：趋势可视化不引入重型图表库，优先纯 CSS/SVG 或极轻量方案（延续 NFR5/DEC-26）。
- **NFR6**：AI 调用按需触发，避免进页面即耗模型；深度分析的多次模型调用需成本可控。
- **NFR7**：构建/运行/测试遵循 DEC-15/16（Docker + SSH + Git 中转，本地不跑）。

## Acceptance Criteria（验收标准）

- [ ] 学情页进入即见结构化面板（正确率 + 薄弱知识点 + 趋势图），无需等 AI。
- [ ] AI 深度错因报告能归纳错因类型（含用户所选错误选项的干扰项分析），不只是知识点分布统计。
- [ ] AI 产出分阶段学习计划，并拆解为可"一键开练"的具体任务，点击跳转到对应筛选的练习/错题视图。
- [ ] 任务/知识点掌握判定基于"连续多次稳定达标"，单次达标不算掌握。
- [ ] 达标后系统自动标记任务完成、更新薄弱点状态，下一次分析自动感知。
- [ ] 阶段快照固定落库，形成时间序列；整体正确率曲线 + 每知识点趋势可查看。
- [ ] AI 能基于趋势解读好转/恶化，并据此重排计划。
- [ ] AI 生成的报告/计划/任务缓存落库，可追溯；结构化数据走 REST，AI 文本走 SSE。
- [ ] 所有新增 API 契约在 `@exam/shared` 定义，前后端共享。

## Decisions（供下游 research / design 继承）

沿用 MVP 的 **DEC-1..DEC-21** 与 v2 的 **DEC-22..DEC-28**，本轮新增：

1. **DEC-29 [confirmed]**：整个深度学情模块建在既有 **Fastify + SQLite + pi SDK + React** 之上，不做架构重构（延续 DEC-22）。*evidence: 数据地基已具备 — `attempts.answered_at`（时间序列）+ `attempts.user_answer`（深度错因）+ `questions.tags`（知识点切片），`schema.ts` 确认。*
2. **DEC-30 [confirmed]**：阶段快照与 AI 产出**固定落库**（新增快照表 + 学习计划/任务表），不每次从 attempts 现算——支撑"多次稳定才算掌握"与"周期趋势对比"，并缓存 AI 产出。*evidence: `LearningDataCollector` 现为无状态横截面计算，无历史点。*
3. **DEC-31 [confirmed]**：AI 产出形态 = **分阶段学习计划 + 一键开练任务**（完整教练形态），而非仅文本报告。任务复用既有 `PracticeScope`（byTag/wrong 等 mode）实现一键跳转。
4. **DEC-32 [confirmed]**：掌握判定 = **连续多次稳定达标**（连续 N 次正确率 ≥ 阈值，具体 N 与阈值待 design 定），防侥幸——非单次达标即掌握。
5. **DEC-33 [confirmed]**：错因分析 = **深度错因归类**（结合题目内容 + 用户所选错误选项 + 答疑追问，归纳概念混淆/计算失误/审题/盲区），非仅统计知识点分布。数据前提已满足（`attempts.user_answer` 存完整作答）。
6. **DEC-34 [confirmed]**：趋势粒度 = **整体 + 每知识点**双维时间序列。
7. **DEC-35 [confirmed]**：AI 调用时机 = **面板即时（REST）+ AI 深度产出按需生成（SSE + 落库缓存）**，避免进页面即耗模型（延续 DEC-24）。
8. **DEC-36 [confirmed]**：本轮范围 = **诊断 + 计划 + 任务闭环 + 趋势一次到位全做**（用户明确"一次到位全做"）。

## Open Questions（待 research/design 阶段解答）

- OQ1：阶段快照的落库触发口径——按时间周期（每日/每周）、按练习会话结束、还是手动触发？每个快照存哪些字段（整体 accuracy + 每 tag 的 wrong/total）最简且够用？
- OQ2：掌握判定的 N 与阈值具体取值？"连续 N 次"的计数窗口以什么为单位（按任务重练轮次 / 按 attempts 序列 / 按知识点最近 K 次作答）？
- OQ3：学习计划/任务的数据模型——计划与任务是两张表还是一张表带层级？任务与 `PracticeScope` 如何映射（任务里存 scope JSON 直接喂给 `/api/practice/start`）？
- OQ4：错因归类是让 AI 自由归纳还是给定固定枚举（概念混淆/计算失误/审题/盲区）让 AI 分类？归类结果是否落库（供趋势统计错因模式变化）还是仅在报告文本里体现？
- OQ5：干扰项分析（哪个错误选项被选最多）在后端结构化聚合（走 REST 面板）还是仅作为 AI prompt 的输入信号？
- OQ6：AI 深度产出的缓存失效策略——"数据有明显变化"如何量化（新增 N 题 / 完成任务 / 距上次生成超过 T 时间）？
- OQ7：单实例本地部署下，阶段快照的周期性落库靠什么触发（无常驻定时任务时，是否改为"进页面时若距上个快照超过周期则补一个"）？
- OQ8：任务完成 → 掌握判定 → 薄弱点状态更新 → 错题本软标记（DEC-28）联动的具体数据流与幂等性如何设计？
