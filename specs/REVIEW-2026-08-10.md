## 一、背景与定位

**立项背景**（FRD，2026-07-16）：备考学生刷题痛点不是"判对错"（程序即可），而是**做完没人讲、错了不知道为什么错、错完就忘、不知道哪块薄弱**。系统定位"AI 原生考试助手"：AI 价值集中在**逐题讲解、错题多轮追问答疑、错因与学情归纳、导入时 AI 解析题目**。核心用户为自学备考学生（单用户本地工具），内容全部用户导入。

**演进脉络**：

- **v1（MVP）**：粘贴/文件导入 → 刷题判分 → AI 讲解 → 错题本 → 学情分析闭环（Phase 1-9）
- **v2**（7/18）：题库管理（建库/重命名/单题 CRUD/移动复制/批量标签）、练习会话+成绩单、错题掌握标记、学情可视化、Provider 管理
- **v3（deep-ai-insights）**：设计完成（88KB 设计文档 + slice3-6 代码），**代码悬空未落地**

**关键决策链**（DEC-1~19）：判分不用 AI（确定性）；AI 只做讲解/答疑/学情/解析；React+Vite+TS / Node+TS / SQLite；pi agent SDK 集成、后端持 Key 代理；SSE 流式（非 WebSocket）；答疑历史以 pi JSONL 为真相源；导入用 inMemory 会话；删题级联删 JSONL；Fastify；**Docker 部署、本地绝不装依赖（DEC-15）**；Key 加密存卷内 SQLite。

**部署位置**：局域网 `192.168.3.11`（git origin: `ssh://skillre@192.168.3.11/Users/skillre/apps/exam-assistant.git`），Docker 双容器，访问 `http://192.168.3.11:8080`。

## 四、系统架构

```
packages/shared ── 共享类型（前后端唯一类型源）
packages/server ── Fastify + better-sqlite3 + pi agent SDK
   ├─ routes/        路由薄层：校验+编排+错误映射（无 SQL）
   ├─ repositories/  纯数据访问（无业务编排）
   ├─ ai/AiService   唯一接触 SDK 层（Key 隔离）
   ├─ grading/       确定性纯函数判分（不经 AI）
   └─ import/insights/crypto/
packages/client ── React+Vite，5 Tab 页（无路由库）
部署：web(Nginx 静态+反代/SSE 透传) + api(Fastify)，app-data 命名卷
```

**架构亮点**：FK 级联全开 + JSONL 路径引用（无孤儿）；AES-256-GCM Key 加密链（明文只存活内存）；SSE 双保险（nginx off + X-Accel-Buffering）；SQL 全参数化；导入 zod 交叉校验 + commit 复检；Markdown DOMPurify 消毒。
